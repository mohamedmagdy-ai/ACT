# تحديث v1.3.26 — إصلاح تنبيه النواقص (كان بيرجع يتفعّل لوحده) + تغيير الحد الافتراضي لـ1

## المشكلة اللي بلّغت عنها

بعد ما عدّلت اسم صنف (تصحيح اسم ماركة Breville)، لاحظت إن التنبيهات ("🔔 نواقص") بتاعة الأصناف بتتفعّل من غير ما تطلب كده.

## السبب الحقيقي

في شاشة "تعديل منتج"، أي حفظ لأي صنف — حتى لو كنت بتعدّل حاجة تانية خالص زي الاسم — كان بيعيد كتابة "حد التنبيه" بالقاعدة دي:

```
p.alert = parseFloat(قيمة الخانة) || 5
```

المشكلة: لو الصنف كان تنبيهه متوقف عمدًا (يعني حد التنبيه = 0، زي أي صنف كتمّته بزرار 🔕)، فالقيمة "0" في JavaScript بتتحسب "فاضية"، فالمعادلة دي كانت بترجّعها 5 تلقائيًا — يعني أي حفظ لأي تعديل في الصنف كان بيشغّل تنبيهه تاني من غير قصد.

## الإصلاح

- دلوقتي البرنامج بيفرّق صح بين "الخانة فاضية فعلاً" (يبقى يدّي القيمة الافتراضية) و"الخانة فيها 0 مكتوب فعلاً" (يبقى يحترم الـ0 ويسيبه زي ما هو). التنبيه المتوقف بيفضل متوقف مهما عدّلت في الصنف حاجات تانية.

## طلبك الإضافي: تغيير الحد الافتراضي من 5 لـ1

- أي **منتج جديد** هيتعمل من دلوقتي، حد التنبيه الافتراضي بقى **1** بدل 5.
- كل الأصناف **الموجودة حاليًا** اللي كانت لسه على القيمة الافتراضية القديمة (5) — من غير ما حد يغيّرها يدويًا لرقم تاني — بقت **1** تلقائيًا أول ما تفتح البرنامج بالنسخة دي.
- الأصناف اللي كانت **متوقف تنبيهها عمدًا** (0) أو اللي كان ليها **حد مخصص** (زي 10 أو 3) — **متلمستش خالص**، فضلت زي ما هي بالظبط.

- `app/index.html`
- `package.json` (النسخة 1.3.26)

## خطوات التطبيق

```
npm run dist
```
